# 导航页插件（命令型）

Gately 的第一个命令型插件：静态链接按分组展示，页内搜索做客户端过滤。
只用 Python 标准库，形态与 `examples/plugin-hello/` 一致（见
`docs/plugin-protocol-v1.md`）。

## 运行

```sh
chmod +x nav.py
# 本地直跑（不用 Gately 时）：PLUGIN_PORT=18081 ./nav.py
# 然后 curl http://127.0.0.1:18081/ 与 /health、/api/links
```

## 在 Gately 里安装（本地目录安装）

本目录自带 `plugin.json` 清单，可直接作本地目录安装的测试夹具：

管理界面 → 插件中心 → 插件市场 → 从本地目录安装 → 填本目录路径 →
安装后即注册为命令型插件（entry `nav.py` 解析为安装目录下的绝对路径，
工作目录即安装目录），点“打开”即见导航页。

手动注册方式：类型选命令，可执行文件填本文件绝对路径，端口填 `0`
（自动分配），健康检查填 `/health`，启用。

## 访问与权限

页面经 Gately 反代访问，走 Gately 登录会话：admin 与只读账号都能看。
写操作按反代注入的 `X-Gately-Role` 区分——只读账号只看链接、不见编辑
入口；admin 可增删改分组与链接、导入数据。服务端对写接口强制校验，
不是只靠页面隐藏。直接访问插件端口（无反代头）时按只读处理，写接口
返回 403；插件本身只绑回环地址，不对外暴露。

## 数据：links.json 在哪、升级会怎样

- 默认路径：插件安装目录下的 `links.json`（即配置目录的
  `plugins/nav/links.json`）。本目录自带的 `links.json` 只是示例种子，
  安装时随包复制过去，之后在页面里的改动都写进安装目录那份。
- **升级会替换安装目录**：升级即按新包重新安装，安装目录会被新包内容
  覆盖，存在默认路径的数据会被种子文件盖掉。**升级前请先点“导出 JSON”
  备份，升级后再点“导入 JSON”恢复。**
- 想让数据跨升级保留：把选项里的 `dataFile` 改成安装目录之外的路径
  （例如 `/etc/gately/nav-links.json`，须保证 Gately 进程可读写），数据就
  不再随安装目录被替换。选项改动后命令型插件会重启一次以注入新值。

## 导入 / 导出

页面上有“导出 JSON”（所有人可见，下载当前 `links.json` 内容）与
“导入 JSON”（仅 admin 可见，选文件后整体替换当前数据，非法内容会被
服务端校验拒绝）。数据可迁移：导出文件拿到任何一处装了本插件的 Gately
上导入即可。

## 选项（PLUGIN_OPTIONS）

插件启动时从 `PLUGIN_OPTIONS` 环境变量读 JSON，支持：

- `title`：页标题，缺省“导航页”。
- `dataFile`：links.json 的存放路径，缺省为插件文件同目录的
  `links.json`。见上节升级说明。

选项在插件中心以 JSON 文本编辑；改动后运行中的命令型插件重启一次
以注入新值。

## v1 局限

- 不探测目标站点存活：链接只是静态展示，点击才跳转；v1 不从 Gately
  主机向外探活。
- 页面只用相对链接（`api/links`），在反代路径
  `/api/plugin/pages/nav/` 下与直接访问端口时都能工作；插件自身不设
  `X-Frame-Options`，iframe 展示不受影响。
- 导入是整体替换，不是合并；URL 只接受 `http://` / `https://` 开头。
